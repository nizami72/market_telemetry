## Алгоритм автоматического выбора TP (Version 1.0)

### Цель

Автоматически определить оптимальное значение **Take Profit (TP)** для каждой модели (M15, M30, M45, M60) на основе последних **30 дней** рыночной истории.

TP должен отражать **текущую волатильность рынка**, а не быть заранее заданной константой.

---

## Входные данные

* Feature Store за последние 30 дней.
* OHLC-свечи с интервалом **10 секунд**.
* Горизонт модели:

    * M15 → 90 свечей
    * M30 → 180 свечей
    * M45 → 270 свечей
    * M60 → 360 свечей

---

## Шаг 1. Выбор точки входа

Для каждой строки:

```text
EntryPrice = Open
```

---

## Шаг 2. Просмотр будущего окна

Для каждой строки просматриваются следующие **N** свечей, где

```text
N = horizon_rows
```

Например для M15:

```text
N = 90
```

---

## Шаг 3. Расчет максимального движения

Для выбранного окна определяется

```text
FutureHigh = max(High)
FutureLow  = min(Low)
```

Затем вычисляются два значения

```text
UpMove   = FutureHigh - EntryPrice
DownMove = EntryPrice - FutureLow
```

Например

```text
EntryPrice = 70000

FutureHigh = 70380
FutureLow  = 69720

UpMove   = 380
DownMove = 280
```

---

## Шаг 4. Формирование распределения

Для всех строк датасета формируются два массива

```text
UpMove[]
DownMove[]
```

Каждый массив содержит одно значение для каждой точки входа.

---

## Шаг 5. Поиск TP

Выбирается такое значение TP, при котором примерно **40–45%** всех окон достигают этого уровня.

Практически это выглядит так:

|  TP | Доля окон, где UpMove ≥ TP |
| --: | -------------------------: |
| 150 |                        72% |
| 200 |                        61% |
| 250 |                        54% |
| 300 |                        46% |
| 350 |                        39% |
| 400 |                        33% |

Для LONG выбирается

```text
TP = 300
```

поскольку около **46%** окон смогли пройти это расстояние.

Аналогично строится таблица для SHORT:

|  TP | Доля окон, где DownMove ≥ TP |
| --: | ---------------------------: |
| 150 |                          74% |
| 200 |                          63% |
| 250 |                          55% |
| 300 |                          44% |
| 350 |                          37% |

---

## Шаг 6. Выбор итогового TP

На первом этапе проекта используется единое значение

```text
TP = SL
```

Итоговый TP выбирается как значение, обеспечивающее близкую долю успешных движений как для LONG, так и для SHORT.

Если распределения отличаются незначительно, используется их общее значение.

Например

```text
M15

TP = 300

SL = 300
```

---

## Шаг 7. Сохранение результата

Выбранное значение сохраняется в соответствующий файл метаданных модели.

Например

```json
{
    "model": "M15",
    "tp": 300,
    "sl": 300,
    "window_days": 30,
    "generated_at": "2026-07-13"
}
```

---

## Принципы алгоритма

* TP не задается вручную.
* TP пересчитывается ежедневно.
* TP зависит только от последних 30 дней истории.
* Каждая модель (M15, M30, M45, M60) получает собственное значение TP.
* Цель выбора TP — сформировать обучающую задачу с достаточным количеством положительных примеров (около 40–45%), что обеспечивает хорошую обучаемость модели и адаптацию к текущей волатильности рынка.
