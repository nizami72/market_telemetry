# Feature Store Specification v1.0

## Назначение

Feature Store является **единственным источником рыночных данных** для всех этапов системы:

* генерации Label;
* обучения моделей;
* тестирования;
* инференса.

Feature Store **никогда не содержит Label** и не зависит от конкретной модели (M15, M30, M45, M60).

Все изменения алгоритма разметки или обучения выполняются без изменения Feature Store.

---

# Формат данных

Каждая запись соответствует **одной 10-секундной свече**.

Минимальный набор полей:

| Поле      | Тип            | Описание                        |
| --------- | -------------- | ------------------------------- |
| timestamp | datetime (UTC) | Время начала 10-секундной свечи |
| open      | float          | Цена открытия                   |
| high      | float          | Максимальная цена за свечу      |
| low       | float          | Минимальная цена за свечу       |
| close     | float          | Цена закрытия                   |

После OHLC располагаются рассчитанные признаки (Feature Engineering).

Например:

| Поле             | Тип   |
| ---------------- | ----- |
| imbalance_5      | float |
| imbalance_20     | float |
| imbalance_50     | float |
| market_delta_10s | float |
| trade_speed_10s  | float |
| ...              | ...   |

Количество признаков может увеличиваться без изменения структуры Feature Store.

# Требования

* Все записи должны быть строго отсортированы по `timestamp` в порядке возрастания.
* Интервал между соседними строками — **10 секунд**.
* Временная зона — **UTC**.
* Не допускаются дублирующиеся `timestamp`.
* Не допускаются пропуски OHLC-значений.
* Все рассчитанные признаки должны относиться только к текущему моменту времени и не использовать информацию из будущего (без look-ahead bias).

---

# Формат хранения

Рекомендуемый формат хранения:

```text
Parquet
```

Причины выбора:

* компактный размер файлов;
* высокая скорость чтения и записи;
* сохранение типов данных;
* эффективная работа с большими объемами исторических данных.

CSV допускается только как промежуточный формат обмена данными.

---

# Основные принципы

1. Feature Store является неизменяемым источником данных.
2. Feature Store никогда не содержит Label.
3. Все модели используют один и тот же Feature Store.
4. Изменение алгоритма Label Generator не требует изменения Feature Store.
5. Добавление новых признаков допускается без изменения существующей структуры данных.
