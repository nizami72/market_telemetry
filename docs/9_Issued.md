# BTC AI Trading v2

## Утвержденная спецификация (Version 1.0)

---

# Цель проекта

Разработать каскад моделей машинного обучения, которые по текущему состоянию рынка оценивают вероятность успешного движения цены в заданном направлении за фиксированный временной горизонт.

Модели используются торговым роботом, который после открытия позиции сразу выставляет TP и SL на стороне биржи.

---

# Горизонты моделей

Используются четыре независимые модели.

| Модель | Горизонт | Количество 10-секундных свечей |
| ------ | -------: | -----------------------------: |
| M15    | 15 минут |                             90 |
| M30    | 30 минут |                            180 |
| M45    | 45 минут |                            270 |
| M60    | 60 минут |                            360 |

Каждая модель обучается независимо.

---

# Переобучение

Модели переобучаются один раз в сутки.

Для обучения используется скользящее окно последних 30 дней.

После каждого переобучения:

* добавляются данные последних суток;
* удаляются самые старые сутки;
* пересчитываются TP;
* заново генерируются Label;
* выполняется обучение модели.

---

# Feature Store

Feature Store является единственным источником рыночных данных.

Он никогда не содержит Label.

Формат:

```text
timestamp
open
high
low
close

imbalance_5
imbalance_20
imbalance_50

market_delta_10s
trade_speed_10s

...
```

Данные хранятся с интервалом 10 секунд.

---

# Цена входа

Для генерации Label используется

```text
EntryPrice = Open
```

---

# Выбор TP

TP не является фиксированной константой.

Для каждой модели он определяется автоматически по статистике последних 30 дней.

Каждая модель получает собственное значение TP.

На первом этапе:

```text
TP = SL
```

---

# Начало проверки

После определения точки входа текущая свеча больше не анализируется.

Проверка начинается со следующей 10-секундной свечи.

Это исключает использование информации из будущего (look-ahead bias).

---

# Алгоритм генерации Label

Для каждой записи вычисляются уровни

```text
LONG_LEVEL = EntryPrice + TP

SHORT_LEVEL = EntryPrice - TP
```

После этого последовательно просматриваются свечи внутри выбранного горизонта.

---

## LONG

Если

```text
High >= LONG_LEVEL
```

произошло раньше достижения SHORT,

то

```text
Label = LONG
```

---

## SHORT

Если

```text
Low <= SHORT_LEVEL
```

произошло раньше достижения LONG,

то

```text
Label = SHORT
```

---

## FLAT

Если за весь горизонт не достигнуты ни LONG, ни SHORT,

то

```text
Label = FLAT
```

---

## UNKNOWN

Если внутри одной и той же свечи одновременно выполнены условия

```text
High >= LONG_LEVEL

и

Low <= SHORT_LEVEL
```

то определить направление невозможно.

В этом случае

```text
Label = UNKNOWN
```

Такие записи не используются при обучении модели.

---

# Кодировка классов

| Код | Класс   |
| --: | ------- |
|   0 | FLAT    |
|   1 | LONG    |
|   2 | SHORT   |
|   3 | UNKNOWN |

---

# Формат Label Store

Для каждого горизонта создается отдельный файл.

Например

```text
m15.parquet
```

Структура:

| Поле           | Описание                                           |
| -------------- | -------------------------------------------------- |
| timestamp      | время исходной записи                              |
| label          | код класса                                         |
| hit_after_rows | через сколько 10-секундных свечей был достигнут TP |

Для FLAT и UNKNOWN

```text
hit_after_rows = -1
```

---

# Meta-файл

Для каждого горизонта создается отдельный файл метаданных.

Например

```text
m15_meta.json
```

Он содержит:

* дату генерации;
* размер обучающего окна;
* горизонт модели;
* количество свечей горизонта;
* TP;
* SL;
* количество записей;
* количество LONG;
* количество SHORT;
* количество FLAT;
* количество UNKNOWN;
* среднее количество свечей до достижения LONG;
* среднее количество свечей до достижения SHORT.

---

# Неизменяемые принципы версии 1.0

1. Используются четыре независимые модели.
2. Каждая модель обучается только на своем временном горизонте.
3. Обучение выполняется ежедневно.
4. Используется скользящее окно последних 30 дней.
5. TP определяется автоматически отдельно для каждого горизонта.
6. На первом этапе используется TP = SL.
7. Feature Store никогда не содержит Label.
8. Label Store генерируется отдельно.
9. Проверка достижения TP начинается со следующей свечи после точки входа.
10. Записи с классом UNKNOWN исключаются из обучения.
