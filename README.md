# 🤖 Market Telemetry ML Pipeline

Инфраструктура сбора телеметрии стакана/ленты Биткоина и конвейер машинного обучения на базе **LightGBM** для прогнозирования 15-минутных ценовых импульсов.

## 🛠️ Системные требования и зависимости

Пайплайн работает локально в виртуальном окружении Python.

```bash
# Установка необходимых библиотек
pip install pandas numpy lightgbm scikit-learn joblib

```

---

## 🏃‍♂️ Быстрый старт (Порядок запуска)

Пайплайн состоит из 4 последовательных этапов. Каждый следующий скрипт зависит от результатов работы предыдущего.

```
[ Logger ] ──(сырые данные)──> [ Labeler ] ──(матрица фичей)──> [ Train ] ──(модель .pkl)──> [ Backtester ]

```

### Шаг 1: Сбор сырых данных (Логгер)

Запусти логгер для автономного сбора телеметрии рынка. Он сохраняет моментальные снимки стакана и дельты каждые 10 секунд.

```bash
python multidim_logger.py

```

* **Выходной файл:** `data/multidim_market_data.csv`
* *Примечание:* Для обучения качественной модели рекомендуется оставить логгер работать в фоне минимум на 1–2 дня до накопления 15 000+ строк.

### Шаг 2: Внедрение контекста и фильтрация шума (Разметчик)

Скрипт рассчитывает скользящие окна (Z-Score скорости, кумулятивную дельту за 2/5 минут, скорость плит) и размечает чистые 15-минутные импульсы (> $40), отсекая флэт.

```bash
python src/market_telemetry/labeler.py

```

* **Вход:** `data/multidim_market_data.csv`
* **Выходной файл:** `src/market_telemetry/data/multidim_labeled_market_data.csv` (очищенная матрица фичей).

### Шаг 3: Обучение градиентного бустинга (Обучение)

Обучает модель `LightGBM` на хронологической выборке (первые 80% данных) и проверяет базовую точность на отложенном тесте (последние 20%).

```bash
python src/market_telemetry/lgbm_train.py

```

* **Вход:** `src/market_telemetry/data/multidim_labeled_market_data.csv`
* **Выходной файл:** `lgbm_market_model.pkl` (сохраненные веса модели).

### Шаг 4: Торговая симуляция (Бэктестер)

Запускает симулятор торговли на тестовом куске истории, проверяя реальное математическое ожидание модели с использованием жестких ордеров `Take Profit` и `Stop Loss`.

```bash
python src/market_telemetry/lgbm_backtester.py

```

* **Вход:** `src/market_telemetry/data/multidim_labeled_market_data.csv` + `lgbm_market_model.pkl`
* **Вывод:** Финансовый отчет в USDT, количество сделок, соотношение прибыльных `TP` к убыточным `SL`.

## 🔬 Архитектурные параметры для экспериментов

Если ты хочешь изменить логику работы системы, ключевые ручки находятся здесь:

* **Масштаб прогноза и фильтр шума** (`labeler.py`):
* `look_ahead = 90` — горизонт прогнозирования в будущее (90 шагов по 10 сек = 15 минут).
* `noise_threshold = 40.0` — минимальное движение цены в $, которое ИИ считает истинным импульсом.


* **Торговые риски** (`lgbm_backtester.py`):
* `confidence_threshold = 0.55` — порог уверенности модели для входа в сделку (55%+).
* `tp_sl_size = 55.0` — размер защитного ордера Take Profit и Stop Loss в $.
* `commission_rate = 0.0006` — торговая комиссия биржи за один ордер.

## 🏗️ Промышленный паспорт комплекса `market_telemetry`

На сервере **Hetzner VPS** развернута автономная экосистема из **5 взаимосвязанных элементов**, где каждый компонент имеет строго свою зону ответственности (*Separation of Concerns*):

```
                     АРХИТЕКТУРА НА СЕРВЕРЕ (PRODUCTION)
                     
       ┌────────────────────────────────────────────────────────┐
       │ 1. multidim_logger.py (Сборщик тиков 24/7)             │
       └──────────────────────────┬─────────────────────────────┘
                                  │ 
                                  ▼ Пишет тики в CSV
       ┌────────────────────────────────────────────────────────┐
       │ 4. market_regime.py (Анализатор волатильности / ATR)    │
       └──────────────────────────┬─────────────────────────────┘
                                  │ 
                                  ▼ Раз в час обновляет метаданные
       ┌────────────────────────────────────────────────────────┐
       │ 5. config.ini (Единый файл конфигурации системы)       │
       └──────────────────────────┬─────────────────────────────┘
                                  │ 
                                  ▼ Служит источником макро-параметров
       ┌────────────────────────────────────────────────────────┐
       │ 3. bybit_live_trader.py (Боевой асинхронный робот)     │
       │    Слушает WebSocket Bybit, шлёт ордера по API         │
       └──────────────────────────▲─────────────────────────────┘
                                  │ 
                                  │ Подгружает веса (joblib.load)
       ┌──────────────────────────┴─────────────────────────────┐
       │ 2. lgbm_market_model.pkl (Готовый бинарник «Мозгов»)    │
       │    * Прилетает с домашнего ПК после обучения * │
       └────────────────────────────────────────────────────────┘

```

### 📋 Техническая спецификация компонентов

#### 1. `multidim_logger.py` (Сборщик Телеметрии)

*
**Статус:** Работает в фоне 24/7 как неубиваемая служба `systemd`.


*
**Логика:** Каждые 10 секунд делает моментальный снимок физики рынка (срез стакана + лента сделок) и складывает тики в файл `/root/multidim_market_data.csv`.


*
**Безопасность:** За его размером следит системный демон Linux `logrotate`, который раз в месяц сжимает архив и защищает SSD от переполнения.



#### 2. `lgbm_market_model.pkl` (Бинарный файл весов ИИ)

*
**Статус:** Статический файл «мозгов» LightGBM.


*
**Логика:** Он **никогда не обучается на сервере**, чтобы не грузить CPU и не вызывать микросекундные задержки (*latency*) исполнения ордеров. Раз в 1–2 недели ты скачиваешь накопленный Big Data лог домой, обучаешь модель на домашней видеокарте/процессоре и закидываешь обновленный `.pkl` по `scp` обратно на сервер.



#### 3. `bybit_live_trader.py` (Сердце Торговли)

*
**Статус:** Асинхронный процесс, непрерывно висящий в RAM сервера.


* **Логика:** Исполнитель. Он держит живое WebSocket-соединение с Bybit. Каждые 10 секунд берет срез рынка, на лету рассчитывает макро-фичи (`speed_ratio`, `cum_delta`) и скармливает вектор модели. Если ИИ выдает вероятность выше порога из `config.ini`, бот шлет ордер на биржу, выставляя жесткие уровни TP/SL и защищая капитал правилом 1% риска от баланса.



#### 4. `market_regime.py` (Математический оркестратор)

*
**Статус:** Просыпается по Cron-планировщику раз в час.


*
**Логика:** Считывает последние 24 часа тиков и вычисляет реальный ATR (средний размах 15-минутных свечей BTC). Если рынок летит — он включает режим «Шторм» ($450), если заснул — режим «Штиль» ($300).



#### 5. `config.ini` (Динамический коммутатор)

*
**Статус:** Текстовый конфиг, связывающий математику рынка с логикой робота.


* **Логика:** Служит «мостом». `market_regime.py` перезаписывает его на лету, а боевой робот `bybit_live_trader.py` мгновенно (на следующей 10-секундной итерации) считывает из него новые уровни TP/SL и порог уверенности ИИ, адаптируясь к фазе рынка без перезагрузки процесса.

### 📝 Управление конфигурацией (Если изменил сам файл сервиса)

Если ты зашел внутрь `/etc/systemd/system/telemetry-trader.service` через `vim` и что-то там поменял (например, добавил флаг `-u` или изменил путь), система **не применит это просто так**. Тебе обязательно нужно выполнить этот комбо-набор:

```bash
# 1. Принудительно заставляем systemd перечитать файлы конфигураций с диска
sudo systemctl daemon-reload

# 2. Перезапускаем службу, чтобы она запустилась по новым правилам
sudo systemctl restart telemetry-trader.service

```

### ⏰ Автозапуск при падении или рестарте Hetzner

В файле сервиса мы уже написали `Restart=always`, поэтому если Python упадет из-за разрыва интернета, Linux **сам поднимет его через 5 секунд**.

Но чтобы бот автоматически включался, если сам сервер Hetzner уйдет на перезагрузку, убедись, что служба «включена»:

* **Включить автозапуск службы при старте системы:**
```bash
sudo systemctl enable telemetry-trader.service

```


* **Выключить автозапуск:**
```bash
sudo systemctl disable telemetry-trader.service

```


Низами, по умолчанию в Ubuntu логи системного демона (`journalctl`) хранятся в системе **очень долго — до тех пор, пока они не займут 10% от всего объема твоего жесткого диска**.

Поскольку твой робот пишет логи каждые 10 секунд (а то и чаще), за пару месяцев непрерывной работы они могут раздуться на гигабайты и забить диск твоего сервера Hetzner.

Чтобы контролировать этот процесс, тебе пригодятся две вещи: как проверить текущий размер логов и как их ограничить.

---

### 1. Как проверить, сколько места логи занимают прямо сейчас

Выполни на сервере команду:

```bash
journalctl --disk-usage

```

Она покажет точный размер, например: `Archived and active journals take up 1.2GB in the file system.`

---

### 2. Как принудительно очистить старые логи руками

Если ты видишь, что места осталось мало, ты можешь удалить всё, кроме самых свежих данных.

* **Очистить всё, кроме логов за последние 3 дня (Рекомендуется):**
```bash
sudo journalctl --vacuum-time=3d

```


* **Или ограничить логи строго по размеру (например, оставить не больше 500 Мегабайт):**
```bash
sudo journalctl --vacuum-size=500M

```



---

### 3. Как настроить автоматическое ограничение логов (Чтобы забыть об этом)

Чтобы диск на Hetzner никогда не переполнился сам по себе, лучше один раз сказать системе: *«Удаляй старые логи автоматически, когда они превысят 500 МБ»*.

1. Открой системный конфиг логов:
```bash
sudo vim /etc/systemd/journald.conf

```


2. Найди строку `#SystemMaxUse=` (она обычно закомментирована знаком `#`).
3. Раскомментируй её (убери `#`) и пропиши лимит:
```ini
SystemMaxUse=500M

```


4. Сохрани и выйди (`:wq`), затем перезапусти службу логирования, чтобы применить правило:
```bash
sudo systemctl restart systemd-journald

```



Теперь Linux сам будет аккуратно подчищать хвосты, на сервере всегда будет свободное место, а твой RAM-буфер продолжит спокойно собирать историю!
